# Deploying OpenThreat (VPS, `main` branch)

```
 GitHub                                      VPS (rootless Podman + Quadlet + systemd --user)
 ──────                                      ────────────────────────────────────────────────
 merge / Dependabot auto-merge on main        openthreat-deploy.timer (every 5 min)
   └─ Actions: Images                           └─ deploy/deploy.sh
        audit, unit + smoke tests                    origin/main new? images sha-<commit> on GHCR?
        full-stack test (compose)                    (no → CI not done, next run)
        push ghcr.io/<owner>/…:sha-<commit>          verified pg_dump backup
   └─ Actions: Deploy test (deploy/** changes)       checkout, tag images :current (old → :previous)
        install/migration, deploy, rollback,         render units, migrations
        crash + reboot on a real systemd             restart app units, health check
                                                     failed → previous images + code
```

Nothing in GitHub can reach the VPS. The VPS only pulls: git (read-only
deploy key) and images from GHCR.

## How it runs

Every container is a systemd user unit generated by Podman Quadlet from
`deploy/quadlet/` (installed to `~/.config/containers/systemd/`):

| Unit | What |
|---|---|
| `openthreat-postgres` / `-redis` | data; only restarted when their unit changes |
| `openthreat-backend` / `-frontend` / `-worker` / `-beat` / `-nginx` | app; restarted on every deploy |
| `openthreat.target` | the whole stack (`systemctl --user stop/start openthreat.target`) |

- `Restart=always`, and a failing health check (backend, frontend, worker)
  kills the container so systemd starts a fresh one.
- Fixed IPs on the private network `openthreat` (`OT_SUBNET`), so nginx
  keeps reaching backend/frontend after they are recreated.
- Data lives in the Podman volumes `openthreat_postgres_data`,
  `openthreat_redis_data`, `openthreat_nginx_cache`. Nothing in deploy/
  ever removes a volume.
- Secrets: `.env` (mode 600) is rendered into `~/.local/state/openthreat/{db,app}.env`;
  Postgres only gets its own credentials.
- Base images (postgres:16, redis:7, nginx) are updated by
  `podman-auto-update.timer` (daily, with automatic rollback).

## One-time setup / migration from podman-compose

As the stack user, in the repo checkout:

```bash
systemctl --user stop openthreat-deploy.timer   # the old compose deploy, if any
git fetch origin && git checkout -B main origin/main
deploy/install.sh
```

`install.sh` checks everything first (Podman version, linger, `.env`, TLS
files in `nginx/ssl/`, subnet). With an existing compose stack it then
makes a verified `pg_dump` (`~/openthreat-backups/*-pre-quadlet.dump`, never
rotated away), counts the CVEs, removes the compose containers (volumes
stay), starts the Quadlet units on the same volumes and compares the
count. If anything fails it prints how to get the old stack back
(`podman-compose up -d` - the data is untouched).

## Day to day

| What | How |
|---|---|
| Ship a change | merge to `main` → CI → live ≤ 5 min after the images are published |
| Status | `deploy/deploy.sh --status` |
| Deploy now | `systemctl --user start openthreat-deploy.service` |
| Deploy log | `journalctl --user -u openthreat-deploy.service -f` |
| App logs | `journalctl --user -u openthreat-backend -f` (or `podman logs -f openthreat-backend`) |
| Roll back | `deploy/deploy.sh --rollback` (previous commit + its images) |
| Redeploy a failed commit | `deploy/deploy.sh --force` |
| Pause auto-deploy | `systemctl --user stop openthreat-deploy.timer` |
| DB shell | `podman exec -it openthreat-postgres sh -c 'psql -U "$POSTGRES_USER" "$POSTGRES_DB"'` |
| One-off app command | `deploy/ot-run.sh -- alembic current` |

A failed deploy is rolled back automatically and that commit is skipped
until a newer one arrives. Migrations are **not** reverted - every deploy
starts with a verified backup in `DEPLOY_BACKUP_DIR` (default
`~/openthreat-backups`, newest 14 kept).

### Full NVD import (resumable)

```bash
systemd-run --user --unit=nvd-full-import --collect \
  "$PWD/deploy/ot-run.sh" -v openthreat_nvd_state:/state -- \
  python scripts/fetch_nvd_complete.py --checkpoint-file /state/nvd_checkpoint.txt
journalctl --user -u nvd-full-import -f
```

Stopping it (`systemctl --user stop nvd-full-import`) loses nothing: every
page is committed and the checkpoint resumes the next run. A deploy
restarts the app but not this import.

### Restore a backup

```bash
systemctl --user stop openthreat-backend openthreat-worker openthreat-beat
podman exec -i openthreat-postgres sh -c \
  'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists' < ~/openthreat-backups/<file>.dump
systemctl --user start openthreat.target
```

## Logs need a persistent journal

If `journalctl --user` says "No journal files were found":

```bash
sudo mkdir -p /var/log/journal
sudo systemd-tmpfiles --create --prefix /var/log/journal
sudo systemctl restart systemd-journald
```
